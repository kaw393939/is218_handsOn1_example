# Install with: python -m pip install -r requirements.txt
#
# == DEPENDENCY LOCK FILE ==
#
# This file locks exact package versions for reproducible environments.
# Think of it as: "To run this project, you need EXACTLY these packages."
#
# How to create this file:
#   1. Install packages manually: pip install pytest
#   2. Lock the environment: pip freeze > requirements.txt
#   3. Commit to git (never modify manually)
#
# Why this matters:
#   - Your teammate clones the repo
#   - They run: pip install -r requirements.txt
#   - They get EXACTLY your versions
#   - No "it works on my machine" mysteries
#
# Each line below shows a package name and EXACT version number.
# The "==" means "this version, nothing else".
#
# These packages are all DEPENDENCIES of pytest (direct or transitive):
#   pytest → requires pluggy, packaging, iniconfig, tomli, etc.
#   We freeze ALL of them to ensure reproducibility.
#
# Real-world scenario:
#   
#   BAD (no lock file):
#   $ pip install pytest
#   # Installs pytest 8.4.2 on Dev's machine
#   $ git clone repo  # Six months later
#   $ pip install pytest
#   # Installs pytest 9.0.0 on QA's machine
#   # Test results differ (breaking changes)
#   # "But it worked for me!"
#
#   GOOD (with requirements.txt):
#   $ pip install -r requirements.txt
#   # Installs pytest 8.4.2 on Dev's machine
#   $ git clone repo  # Six months later
#   $ pip install -r requirements.txt
#   # Installs pytest 8.4.2 on QA's machine
#   # Identical environments, reproducible results
#
# This pattern exists in every language:
#   JavaScript: package-lock.json
#   Java: pom.xml
#   Go: go.sum
#   Rust: Cargo.lock
#   Ruby: Gemfile.lock
#
# Professional teams ALWAYS lock dependencies. It's not optional.
#
